Least-Squares Solvers and Data Preparation

This page documents the building blocks used by opinf and the streaming methods: time-derivative approximation, data-matrix assembly, and the least-squares and Tikhonov solvers. You rarely need to call them directly, but they are useful for custom workflows (e.g., Streaming OpInf, regularization studies, or very large regression problems).

Time derivatives

If time-derivative data are not available from the simulator, they are approximated from the snapshots with finite differences. The scheme is selected by DataStructure.deriv_type:

deriv_typeSchemeOrderSnapshots used (idx)
"FE"forward Euler11:K-1
"BE"backward Euler12:K
"SI"semi-implicit Euler (backward difference)12:K
"FE4"forward difference41:K-4
"BE4"backward difference45:K
"CTD4"central difference43:K-2
"FBCT4"forward/central/backward difference41:K

time_derivative_approx applies the scheme to a snapshot matrix, whereas finite_diff_matrix returns the equivalent sparse matrix $\mathbf{E}$ such that $\dot{\mathbf{X}} \approx \mathbf{X}\mathbf{E}$. The matrix form is what One-pass Streaming OpInf uses, because it can be applied to the compressed snapshot factors.

LiftAndLearn.time_derivative_approx — Function
time_derivative_approx(X, options)

Approximate the time derivative of the snapshot data by finite differences, using the scheme options.data.deriv_type and time step options.data.Δt.

Same as time_derivative_approx(X, options.data.deriv_type, options.data.Δt); see that method for the available schemes and the meaning of idx.

Arguments

  • X::VecOrMat: state snapshot matrix of size $n \times K$ (rows = state, columns = time).
  • options::AbstractOption: OpInf options providing data.deriv_type and data.Δt.

Returns

  • dXdt::Matrix: approximate time derivative of size $n \times K'$.
  • idx::UnitRange{Int}: time indices (columns of X) at which dXdt approximates the derivative, with length(idx) == K'.

time_derivative_approx(X, choice, Δt)

Approximate the time derivative of the snapshot data with the finite-difference scheme choice and time step Δt.

Column j of dXdt approximates $\dot{\mathbf{x}}(t_{\text{idx}[j]})$, so the state data aligned with the derivative data is X[:, idx]. Available schemes:

choicestencilidx$K'$
"FE"1st-order forward difference $(x_{k+1}-x_k)/\Delta t$1:K-1$K-1$
"BE"1st-order backward difference $(x_k-x_{k-1})/\Delta t$2:K$K-1$
"SI"same differences as "BE" (semi-implicit Euler)2:K$K-1$
"FE4"4th-order one-sided forward difference1:K-4$K-4$
"BE4"4th-order one-sided backward difference5:K$K-4$
"CTD4"4th-order central difference3:K-2$K-4$
"FBCT4"4th-order central inside, 4th-order one-sided at the two first/last points1:K$K$

Arguments

  • X::VecOrMat: state snapshot matrix of size $n \times K$ (rows = state, columns = time).
  • choice::String: finite-difference scheme (see table above).
  • Δt::Real: time step between consecutive snapshots.

Returns

  • dXdt::Matrix: approximate time derivative of size $n \times K'$.
  • idx::UnitRange{Int}: time indices (columns of X) at which dXdt approximates the derivative.

Notes

  • An error is thrown for an unknown choice.
  • The 4th-order schemes require $K \geq 5$; "FBCT4" additionally requires Δt::Float64 (it calls fwd4/bwd4).
  • The equivalent linear operator is returned by finite_diff_matrix.

LiftAndLearn.finite_diff_matrix — Function
finite_diff_matrix(fd_method, n, dt)

Build the sparse finite-difference matrix $\mathbf{E}$ of a time-derivative scheme, so that for a snapshot matrix $\mathbf{X}$ with n columns (time steps) the product $\mathbf{X}\mathbf{E}$ equals the derivative approximation returned by time_derivative_approx(X, fd_method, dt).

Column j of $\mathbf{E}$ holds the stencil weights for the derivative at time index idx[j]. The schemes, index ranges and number of columns $K'$ are the same as in time_derivative_approx: "FE" (1:n-1), "BE"/"SI" (2:n), "FE4" (1:n-4), "BE4" (5:n), "CTD4" (3:n-2) and "FBCT4" (1:n).

Arguments

  • fd_method::String: finite-difference scheme ("FE", "BE", "SI", "FE4", "BE4", "CTD4" or "FBCT4").
  • n::Int: number of time steps (columns of the snapshot matrix).
  • dt::Float64: time step.

Returns

  • E::SparseMatrixCSC{Float64,Int}: finite-difference matrix of size $n \times K'$.
  • idx::UnitRange{Int}: time indices at which $\mathbf{X}\mathbf{E}$ approximates the derivative.

Notes

  • Throws an error for an unknown fd_method or if n is too small ($n < 2$ for the first-order schemes, $n < 5$ for the fourth-order schemes).

Data matrix and operator unpacking

LiftAndLearn.get_data_matrix — Function
get_data_matrix(Xhat, Xhat_t, Ut, options; verbose)

Assemble the data matrix $\mathbf{D}$ of the Operator Inference (OpInf) regression problem.

The column blocks of $\mathbf{D}$ are stacked in the following order, according to options.system:

  1. linear state $\hat{\mathbf{X}}^\top$ (symbol :A),
  2. input $\mathbf{U}^\top$ (symbol :B),
  3. polynomial state terms of order $i \geq 2$ (symbols :Aiu with the non-redundant Kronecker product if options.optim.nonredundant_operators, otherwise :Ai),
  4. state-input coupling terms (symbol :N for bilinear, :Ni for higher orders),
  5. a column of ones for the constant term (symbol :K).

Arguments

  • Xhat::AbstractArray: reduced state snapshot matrix of size $r \times K$ (columns = snapshots).
  • Xhat_t::AbstractArray: transpose of Xhat (size $K \times r$).
  • Ut::AbstractArray: tall input data matrix of size $K \times m$.
  • options::AbstractOption: OpInf options defining the system structure.

Keyword Arguments

  • verbose::Bool=true: if true, also return the dimension breakdown and the operator symbols.

Returns

  • D::AbstractMatrix: data matrix of size $K \times d$.
  • dims::Vector: number of columns of each block of D (only if verbose=true).
  • operator_symbols::Vector{Symbol}: operator symbol of each block, in the same order as dims (only if verbose=true).
source

Unpack the operator matrix $\mathbf{O}$ into the fields of operators and, if the system has an output, fit the output operator $\mathbf{C}$.

  • operator_symbols::AbstractArray: operator symbols in the same order as dims.
  • options::AbstractOption: OpInf options (needs system.output, with_reg and λ).

Returns

  • nothing; mutates operators in place.

Notes

  • A warning is emitted if :B is not placed right after :A in operator_symbols.

LiftAndLearn.leastsquares_solve — Function
leastsquares_solve(
    D,
    Rt,
    Yt,
    Xhat_t,
    dims,
    operator_symbols,
    options
)

Solve the Operator Inference (OpInf) regression $\mathbf{D}\mathbf{O}^\top \approx \mathbf{R}^\top$ with or without Tikhonov regularization and unpack the result into an Operators structure.

If options.with_reg is true, a diagonal Tikhonov matrix $\boldsymbol{\Gamma}$ is built from options.λ with tikhonov_matrix! and the problem is solved with tikhonov; otherwise standard_least_squares is used. The solver settings (use_gpu, use_normal_equations, use_backslash, chunk_size, tolerance, ...) are taken from options. If options.system.output is nonzero, the output operator $\mathbf{C}$ is also fitted from Yt and Xhat_t (see unpack_operators!).

Arguments

  • D::AbstractArray: data matrix $\mathbf{D}$ of size $K \times d$ (rows = time).
  • Rt::AbstractArray: transposed derivative data $\mathbf{R}^\top$ of size $K \times r$.
  • Yt::AbstractArray: transposed output data of size $K \times l$.
  • Xhat_t::AbstractArray: transposed reduced state data of size $K \times r$.
  • dims::AbstractArray: number of columns of $\mathbf{D}$ belonging to each operator.
  • operator_symbols::AbstractArray: operator symbols (e.g. :A, :B, :A2u) in the same order as dims.
  • options::AbstractOption: OpInf options (typically an LSOpInfOption).

Returns

  • operators::Operators: the inferred operators; the full operator matrix $\mathbf{O}$ is stored in operators.O.

LiftAndLearn.reproject — Function
reproject(Xhat, V, Ut, op, options)

Generate the derivative data by reprojection, which removes the closure error caused by the truncated POD modes.

For each snapshot $\hat{\mathbf{x}}_i$ the full-order right-hand side $\mathbf{f}(\mathbf{V}\hat{\mathbf{x}}_i, \mathbf{u}_i) = \mathbf{A}\mathbf{x} + \mathbf{B}\mathbf{u} + \mathbf{K} + \mathbf{f}_{\text{nl}}(\mathbf{x}, \mathbf{u})$ of op is evaluated at the reconstructed state and projected back onto V.

Arguments

  • Xhat::AbstractArray: reduced state snapshot matrix of size $r \times K$ (columns = snapshots).
  • V::AbstractArray: basis (e.g. POD basis) of size $n \times r$.
  • Ut::AbstractArray: tall input data matrix of size $K \times m$.
  • op::Operators: full-order model operators. The nonlinear part is op.f if a custom function was supplied, otherwise the default built from the polynomial and bilinear operators of op.
  • options::AbstractOption: OpInf options.

Returns

  • Rt::AbstractArray: reprojected derivative data $\mathbf{R}^\top$ of size $K \times r$.
source
reproject(Xhat, V, Ut, lm, op, options)

Generate the derivative data of a lifted system by reprojection.

For each snapshot the lifted state is reconstructed as $\mathbf{V}\hat{\mathbf{x}}$; the time derivative of the original variables is evaluated with the full-order model op, and the time derivative of the additional lifted variables is approximated by a forward Euler step of size options.data.Δt through the lifting map lm.mapNL. The result is projected back onto V.

Arguments

  • Xhat::AbstractArray: reduced lifted state snapshot matrix of size $r \times K$ (columns = snapshots).
  • V::AbstractArray: basis of the lifted state of size $(N_l \cdot gp) \times r$.
  • Ut::AbstractArray: tall input data matrix of size $K \times m$.
  • lm::lifting: lifting map.
  • op::Operators: full-order operators of the original (unlifted) model. The nonlinear part is op.f if a custom function was supplied (e.g. the cubic term of FitzHugh–Nagumo), otherwise the default built from the polynomial and bilinear operators of op.
  • options::AbstractOption: OpInf options (uses vars.N, vars.N_lift and data.Δt).

Returns

  • Rt::Matrix: reprojected derivative data $\mathbf{R}^\top$ of size $K \times r$.

Least-squares solvers

Unregularized OpInf problems $\min_{\mathbf{O}}\|\mathbf{D}\mathbf{O}^\top - \mathbf{R}\|_F$ are solved by standard_least_squares. Depending on the options in LSOpInfOption it uses backslash (QR), the normal equations, or a memory-aware batched QR/LinearSolve.jl solve, optionally on the GPU.

LiftAndLearn.standard_least_squares — Function
standard_least_squares(
    D,
    Rt;
    use_gpu,
    use_normal_equations,
    chunk_size,
    tolerance,
    use_backslash,
    algorithm,
    estimate_memory,
    max_iterations
)

Solve the least-squares problem $\min_{\mathbf{O}} \|\mathbf{D}\mathbf{O} - \mathbf{R}^\top\|_F$ with automatic selection of the solution method.

With $\mathbf{D}$ of size $m \times n$ and $\mathbf{R}^\top$ of size $m \times p$, the method is chosen in this order:

  1. backslash D \ Rt if the GPU is active or use_backslash=true;
  2. matrix-free normal equations (solve_normal_equations) if use_normal_equations=true and $m > 3n$;
  3. QR decomposition with batched triangular solves (solve_qr_batch) if $p >$ chunk_size;
  4. otherwise a direct LinearSolve.jl solve reusing the factorization (solve_direct_batch).

If an OutOfMemoryError occurs, the solver falls back to the normal-equations method on the CPU.

Arguments

  • D::AbstractArray{T}: data matrix $\mathbf{D}$ of size $m \times n$.
  • Rt::AbstractArray{T}: right-hand-side matrix $\mathbf{R}^\top$ of size $m \times p$.

Keyword Arguments

  • use_gpu::Bool=false: use the GPU (CUDA.jl or Metal.jl) if functional; the backslash solve is used on the GPU.
  • use_normal_equations::Bool=false: use the normal-equations method for strongly overdetermined systems ($m > 3n$).
  • chunk_size::Int=400: number of right-hand-side columns per batch; also the threshold on $p$ above which the QR method is used.
  • tolerance::Real=1e-12: absolute tolerance of the iterative (normal-equations) solver.
  • use_backslash::Bool=false: solve with the backslash operator.
  • algorithm::Union{Function,Nothing}=nothing: LinearSolve.jl algorithm for the direct and normal-equations solves (nothing = LinearSolve.jl default).
  • estimate_memory::Bool=false: log an estimate of the memory usage (see estimate_memory_usage).
  • max_iterations::Int=1000: maximum number of iterations of the iterative solver.

Returns

  • O::AbstractMatrix{T}: solution of size $n \times p$ such that $\mathbf{D}\mathbf{O} \approx \mathbf{R}^\top$.

Notes

  • LSOpInfOption uses different defaults (use_backslash=true, chunk_size=1000) when this function is called from opinf.

Tikhonov-regularized solvers

With with_reg = true, OpInf solves

\[\min_{\mathbf{O}} \|\mathbf{D}\mathbf{O}^\top - \mathbf{R}\|_F^2 + \operatorname{tr}\!\left(\mathbf{O}\,\boldsymbol{\Gamma}\,\mathbf{O}^\top\right), \qquad \mathbf{O}^\top = (\mathbf{D}^\top\mathbf{D} + \boldsymbol{\Gamma})^{-1}\mathbf{D}^\top\mathbf{R},\]

where the diagonal Tikhonov matrix $\boldsymbol{\Gamma}$ is assembled by tikhonov_matrix! from the per-operator weights in TikhonovParameter. The solver tikhonov chooses between an augmented least-squares system, the normal equations, an iterative method, or an SVD with truncation of small singular values.

LiftAndLearn.tikhonov — Function
tikhonov(
    b,
    A,
    Γ;
    tol,
    use_gpu,
    use_normal_form,
    use_svd_truncation,
    use_backslash,
    chunk_size,
    max_iterations,
    estimate_memory,
    preconditioning
)

Solve the Tikhonov-regularized least-squares problem

\[\min_{\mathbf{x}} \|\mathbf{A}\mathbf{x} - \mathbf{b}\|_2^2 + \mathbf{x}^\top\boldsymbol{\Gamma}\mathbf{x} = \|\mathbf{A}\mathbf{x} - \mathbf{b}\|_2^2 + \|\boldsymbol{\Gamma}^{1/2}\mathbf{x}\|_2^2\]

column by column for all right-hand sides in b. In Operator Inference (OpInf), A is the data matrix $\mathbf{D}$, b the derivative data $\mathbf{R}^\top$ and the solution is $\mathbf{O}^\top$.

The solution method is chosen by select_optimal_method: SVD truncation (use_svd_truncation), normal form (use_normal_form), augmented system (use_backslash), or, by default, a matrix-free iterative solver. On OutOfMemoryError it falls back to the iterative solver.

Arguments

  • b::AbstractArray{T}: right-hand side of size $m \times p$.
  • A::AbstractArray{T}: coefficient (data) matrix of size $m \times n$.
  • Γ::AbstractMatrix{T}: Tikhonov matrix $\boldsymbol{\Gamma}$ of size $n \times n$ (symmetric positive semidefinite).

Keyword Arguments

  • tol::Real=1e-12: absolute tolerance of the iterative solvers and relative singular-value cutoff of the SVD-truncation solver.
  • use_gpu::Bool=false: use the GPU (CUDA.jl or Metal.jl) if functional. This forces use_backslash=false, so the augmented-system solver is not selected and only the normal-form solver runs on the GPU.
  • use_normal_form::Bool=false: allow the normal-form solver (used if $m > 2n$ and $p < 100$).
  • use_svd_truncation::Bool=false: allow the SVD-truncation solver (used if the condition estimate exceeds 1e12).
  • use_backslash::Bool=false: use backslash in the augmented-system and normal-form solvers.
  • chunk_size::Int=1000: number of right-hand-side columns per batch.
  • max_iterations::Int=1000: maximum number of iterations of the iterative solvers.
  • estimate_memory::Bool=false: log an estimate of the memory usage (see estimate_tikhonov_memory).
  • preconditioning::Bool=false: stored in the solver configuration (see TikhonovSolver).

Returns

  • x::AbstractMatrix{T}: regularized solution of size $n \times p$.

Notes

  • The iterative solvers stop at an absolute tolerance tol, so their accuracy is lower than that of the direct (backslash) solvers.

Fill the diagonal entries of the Tikhonov matrix $\boldsymbol{\Gamma}$ block by block from the regularization parameters λ.

The entries of Γ are split into consecutive blocks of lengths dims; the block of operator symbol s is set to getproperty(λ, s). For polynomial state operators the first two characters of the symbol are used, so :A2 and :A2u both take λ.A2.

Returns

LiftAndLearn.optimize_regularization_parameter — Function
optimize_regularization_parameter(
    A,
    b,
    Γ_base;
    method,
    n_params
)

Select the scale $\gamma$ of the Tikhonov matrix $\boldsymbol{\Gamma} = \gamma\boldsymbol{\Gamma}_{\text{base}}$ by generalized cross-validation (GCV) over n_params log-spaced values in $[10^{-8}, 10^{2}]$.

For each $\gamma$ the GCV score $K\,\|\mathbf{A}\mathbf{x}_\gamma - \mathbf{b}\|^2 / (K - \mathrm{tr}(\mathbf{A}(\mathbf{A}^\top\mathbf{A}+\boldsymbol{\Gamma})^{-1}\mathbf{A}^\top))^2$ is computed, where $K$ is the length of b.

Arguments

  • A::AbstractMatrix{T}: coefficient (data) matrix of size $K \times n$.
  • b::AbstractVector{T}: right-hand-side vector of length $K$.
  • Γ_base::AbstractMatrix{T}: base Tikhonov matrix of size $n \times n$.

Keyword Arguments

  • method::Symbol=:gcv: selection criterion; only :gcv is supported.
  • n_params::Int=50: number of candidate values of $\gamma$.

Returns

  • γ_opt::Float64: the candidate with the smallest GCV score.
  • scores::Vector{T}: GCV score of each candidate.

Notes

  • Throws an ArgumentError for any method other than :gcv.

estimate_tikhonov_memory(A, b, Γ)
estimate_tikhonov_memory(A, b, Γ, method)

Estimate the memory (in bytes) required by the Tikhonov solution method.

The base memory is sizeof(T)*(m*n + m*p + n*n); :augmented adds sizeof(T)*(m+n)*(n+p), :normal adds sizeof(T)*(n*n + n*p), :svd adds sizeof(T)*3*n*n, and any other symbol returns the base memory.

Arguments

  • A::AbstractMatrix{T}: coefficient (data) matrix of size $m \times n$.
  • b::AbstractArray{T}: right-hand side of size $m \times p$.
  • Γ::AbstractMatrix{T}: Tikhonov matrix (unused).
  • method::Symbol=:auto: :augmented, :normal, :svd or :auto.

Returns

  • mem::Integer: estimated memory in bytes.
