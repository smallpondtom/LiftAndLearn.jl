Options for Model Learning

General Setup Options

System Structure

This package works with model reduction for polynomial systems with affine control taking a generel form of

\[\dot{\mathbf{x}} = \mathbf{A}_1\mathbf{x} + \mathbf{A}_2(\mathbf{x}\otimes\mathbf{x}) + \cdots + \mathbf{A}_n(\underbrace{\mathbf{x}\otimes\cdots\otimes\mathbf{x}}_{n-\text{times}}) + \sum_{i=1}^m N_{1,i}\mathbf{x}\mathbf{u}_i + \cdots + \sum_{i=1}^m N_{k,i}(\underbrace{\mathbf{x}\otimes\cdots\otimes\mathbf{x}}_{k-\text{times}})\mathbf{u}_i + \mathbf{B}\mathbf{u} +\mathbf{K}~.\]

Current Implementations

With the current version we have only implemented up to quartic states and bilinear controls. We plan to implement linear-quadratic controls and other-higher order systems in the future, as these types of systems are observed in many applications.

For such structures, use SystemStructure struct to define the system.

LiftAndLearn.SystemStructure — Type
mutable struct SystemStructure

Polynomial structure of the system whose operators are to be inferred.

Each field lists the polynomial orders present in the corresponding term of the model (0 means the term is absent). For example state=[1, 2] means the state equation has a linear term $\mathbf{A}\mathbf{x}$ and a quadratic term $\mathbf{A}_2(\mathbf{x}\otimes\mathbf{x})$.

Fields

  • state::Union{Array{<:Int,1},Int}=0: polynomial orders of the state terms (e.g. [1, 2] for linear + quadratic).
  • control::Union{Array{<:Int,1},Int}=0: polynomial orders of the input terms (1 adds the linear input operator $\mathbf{B}$).
  • output::Union{Array{<:Int,1},Int}=0: polynomial orders of the output terms (1 adds the linear output operator $\mathbf{C}$).
  • coupled_input::Union{Array{<:Int,1},Int}=0: polynomial orders of the state-input coupling terms (1 adds the bilinear operator $\mathbf{N}$).
  • coupled_output::Union{Array{<:Int,1},Int}=0: polynomial orders of the state-input coupling terms in the output equation.
  • constant::Int=0: nonzero to include a constant term $\mathbf{K}$ in the state equation.
  • constant_output::Int=0: nonzero to include a constant term in the output equation.

Notes

  • The orders are represented as integers or vectors of integers.
  • coupled_output and constant_output are currently not used by the core OpInf routines.

Examples

SystemStructure(state=[1, 2], control=1, output=1, coupled_input=1, constant=1, constant_output=1)

This represents a system that has:

  • linear (=1) and quadratic (=2) state terms,
  • a linear input term,
  • a linear output term,
  • a bilinear (state $\times$ input) coupling term,
  • a constant term in the state equation,
  • a constant term in the output equation.

Variable info

This structure allows you to input information about the variables in the system. For example, the Fitzhugh-Nagumo system has two main variables: a fast-recovery variable (usually denoted as v) and a slow-activating variable (usually denoted as w). The Fitzhugh-Nagumo equation is given by:

\[\begin{align*} \frac{dv}{dt} &= v - \frac{v^3}{3} - w + I \\ \frac{dw}{dt} &= \epsilon (v + a - bw) \end{align*}\]

Additionally, if we lift this system, it becomes a lifted system of 3 variables. For the VariableStructure you can define the number of unlifted state variables N=2 and the number of lifted state variables Nl=3.

LiftAndLearn.VariableStructure — Type
mutable struct VariableStructure

Information about the system variables.

Fields

  • N::Int64=0: number of (unlifted) system variables, e.g. 2 for a system in $(v, w)$.
  • N_lift::Int64=N: number of system variables after lifting (used by Lift & Learn (LnL)).

Data Info

With the DataStructure struct, the user will define the time-step $\Delta t$ and optionally the down-sampling and type of numerical scheme used for the Partial Differential Equation.

LiftAndLearn.DataStructure — Type
mutable struct DataStructure

Information about the snapshot data.

Fields

  • Δt::Float64=0.01: time step between consecutive snapshots.
  • DS::Int64=0: downsampling rate (not used by the core OpInf routines; available for user scripts).
  • deriv_type::String="FE": finite-difference scheme used by time_derivative_approx to approximate the time derivative; one of "FE", "BE", "SI", "FE4", "BE4", "CTD4", "FBCT4".

Optimization Settings

This options is only required if you are dealing with the optimization based model reduction methods (e.g., Energy-Preserving Operator Inference) in which you must select some options for the optimization.

LiftAndLearn.OptimizationSetting — Type
mutable struct OptimizationSetting

Settings for the regression / optimization problem.

Fields

  • verbose::Bool=false: print the solver output of the (EP-OpInf) optimization.
  • initial_guess::Bool=false: warm-start the EP-OpInf optimization with the operators passed as IG.
  • max_iter::Int64=3000: maximum number of Ipopt iterations for EP-OpInf.
  • nonredundant_operators::Bool=true: use the non-redundant (unique Kronecker) form of the polynomial operators (e.g. A2u) instead of the redundant form (e.g. A2).
  • reproject::Bool=false: use the reprojection scheme to generate the derivative data (Lift & Learn (LnL) opinf method).
  • SIGE::Bool=false: successive initial guess estimation; the initial guess IG may be of lower dimension than the model being learned.
  • with_bnds::Bool=false: add box bounds to the EP-OpInf optimization variables.
  • linear_solver::String="none": name of the HSL linear solver passed to Ipopt ("none" keeps the Ipopt default).
  • HSL_lib_path::String="none": path to the HSL library used when linear_solver is set.
source

Reprojection

Reprojection is a sampling scheme used to increase the accuracy of the recovered reduced model. For further details and mathematical proofs refer to [1] and [2].

Successive Initial Guess Estimation (SIGE)

The SIGE option is used to run the optimization successive from a lower reduced dimension and increasing the dimensions sequentially by using the solution of the lower dimensional operator as the initial guess for the next optimization. For example, you will solve the optimization for r=2 and then use the solution to solve for the optimization of r=3.

# r = 2
options.optim.initial_guess = false  # turn off initial guess for the first iteration
op_tmp = LnL.epopinf(Xdata, Vr[:,1:2], options; U=zeros(100), Xdot=Xdotdata)  # compute the first operator
op[1] = op_tmp  # store the first operator

# r =3
options.optim.initial_guess = true  # turn on initial guess for the next step
op_tmp = LnL.epopinf(Xdata, Vr[:,1:3], options; U=zeros(100), Xdot=Xdotdata, IG=LnL.Operators(A=op_tmp.A, A2u=op_tmp.A2u)) # compute the second operator
op[2] = op_tmp

Linear Solvers

For the optimization we use Ipopt, and for its linear solvers it is possible to use the default solvers like MUMPS and HSL solvers (e.g., ma77, ma86, and ma97).

Warning

To use HSL linear solvers you will need to obtain a license from here. Then set the path to the solvers using the option HSL_lib_path:

import HSL_jll
OptimizationSetting.HSL_lib_path = HSL_jll.libhsl_path

Regularization

Using the TikhonovParameter struct you will define the Tikhonov regularization matrix. This will be a diagonal matrix with diagonal entries having different values corresponding to the operators that it is regulating (e.g., linear, quadratic, bilinear).

The Tikhonov regulated optimization problem is defined as

\[\text{min}~\|\mathbf{D}\mathbf{O}^\top - \dot{\mathbf{\hat{X}}}^\top\|^2_F + \|\mathbf{\Gamma}^{1/2}\mathbf{O}^\top\|^2_F\]

where $\mathbf{D}$, $\mathbf{O}^\top$, $\dot{\hat{\mathbf{X}}}$ are the data matrix, operator matrix (with minimizers), and time derivative snapshot matrix, respectively, and $\mathbf{\Gamma}$ is a diagonal matrix whose entries are the values in TikhonovParameter for the corresponding operator blocks. The linear least-squares solution of this becomes

\[\mathbf{O}^\top = (\mathbf{D}^\top\mathbf{D} + \mathbf{\Gamma})^{-1} \mathbf{D}^\top\dot{\mathbf{\hat{X}}}^\top\]

See Least-Squares Solvers for the available solution methods.

LiftAndLearn.TikhonovParameter — Type
mutable struct TikhonovParameter

Tikhonov regularization parameters for each operator.

These values populate the diagonal of the Tikhonov matrix $\boldsymbol{\Gamma}$ (see tikhonov_matrix!) used when LSOpInfOption(with_reg=true). The redundant and non-redundant polynomial operators share the same parameter (e.g. A2 is used for both :A2 and :A2u).

Fields

  • A::Union{Real, AbstractArray{Real}}=0.0: parameter for the linear state operator $\mathbf{A}$ (an array assigns one value per column of $\mathbf{A}$).
  • A2::Real=0.0: parameter for the quadratic state operator.
  • A3::Real=0.0: parameter for the cubic state operator.
  • A4::Real=0.0: parameter for the quartic state operator.
  • B::Real=0.0: parameter for the linear input operator $\mathbf{B}$.
  • N::Real=0.0: parameter for the bilinear state-input operator $\mathbf{N}$.
  • C::Real=0.0: parameter for the linear output operator $\mathbf{C}$ (used when solving the output least-squares problem in unpack_operators!).
  • K::Real=0.0: parameter for the constant operator $\mathbf{K}$ of the state equation.
source

Model Reduction Specific Options

These options are all specific to each solution method of Operator Inference. All of the options below are a subtype of AbstractOption.

LiftAndLearn.AbstractOption — Type
abstract type AbstractOption

Abstract supertype of all Operator Inference option structures (e.g. LSOpInfOption, EPHECOpInfOption, EPSICOpInfOption, EPPOpInfOption).

Functions such as opinf, epopinf, get_data_matrix and time_derivative_approx dispatch on this type and read the system, vars, data and optim fields of the concrete option structure.

Standard Operator Inference

This option is required when using the standard Operator Inference method.

LiftAndLearn.LSOpInfOption — Type
mutable struct LSOpInfOption <: LiftAndLearn.AbstractOption

Options for standard (least-squares) Operator Inference (OpInf), with optional Tikhonov regularization.

When with_reg=false the regression is solved by standard_least_squares; when with_reg=true it is solved by tikhonov with a diagonal Tikhonov matrix $\boldsymbol{\Gamma}$ built from λ. The solver fields below are forwarded to those functions.

Fields

  • method::Symbol=:LS: name of the method.
  • system::SystemStructure=SystemStructure(): polynomial structure of the system.
  • vars::VariableStructure=VariableStructure(): information about the system variables.
  • data::DataStructure=DataStructure(): information about the snapshot data (time step, derivative scheme).
  • optim::OptimizationSetting=OptimizationSetting(): regression settings (e.g. nonredundant_operators, reproject).
  • λ::TikhonovParameter=TikhonovParameter(): Tikhonov regularization parameters (used only if with_reg=true).
  • with_reg::Bool=false: use Tikhonov regularization.
  • use_gpu::Bool=false: solve the regression on the GPU (CUDA.jl or Metal.jl) if one is functional; falls back to the CPU otherwise.
  • use_normal_equations::Bool=false: solve via the normal equations (passed as use_normal_equations to standard_least_squares and as use_normal_form to tikhonov).
  • use_svd_truncation::Bool=false: allow the SVD-truncation solver in tikhonov for ill-conditioned problems (regularized path only).
  • chunk_size::Int=1000: number of right-hand-side columns processed per batch.
  • tolerance::Real=1e-12: numerical tolerance (absolute tolerance of the iterative solvers, relative singular-value cutoff of the SVD-truncation solver).
  • algorithm::Union{Function,Nothing}=nothing: custom LinearSolve.jl algorithm for the non-regularized solve (nothing uses the LinearSolve.jl default).
  • use_backslash::Bool=true: solve with the backslash operator (D \ R for least squares, augmented system $[\mathbf{D}; \boldsymbol{\Gamma}^{1/2}]$ for Tikhonov).
  • estimate_memory::Bool=false: log an estimate of the memory needed by the solver.
  • max_iterations::Int=1000: maximum number of iterations of the iterative solvers.
  • preconditioning::Bool=false: request diagonal preconditioning in the Tikhonov solver.

Notes

  • preconditioning is stored in the Tikhonov solver configuration but is only used by solve_iterative_normal_form, which is not called by the default solve paths.
source
Note

The solver settings (use_backslash, use_normal_equations, use_svd_truncation, tolerance, chunk_size, use_gpu, ...) select how the least-squares problem is solved; see Least-Squares Solvers. The with_tol/pinv_tol options of earlier versions have been removed: use use_svd_truncation=true with tolerance to truncate small singular values instead.

LSOpInfOption is also used to configure Streaming OpInf.

Energy-Preserving Operator Inference Options

The three options below are for the energy-preserving Operator Inference approaches: hard equality constraint, soft inequality constraint, and penalty. For details of each parameter please check out the documentation of EP-OpInf Manual

LiftAndLearn.EPHECOpInfOption — Type
mutable struct EPHECOpInfOption <: LiftAndLearn.AbstractOption

Options for Energy-Preserving OpInf (EP-OpInf) with hard equality constraints (EPHEC).

Fields

  • method::Symbol=:EPHEC: name of the method (used by epopinf for dispatch).
  • system::SystemStructure=SystemStructure(): polynomial structure of the system.
  • vars::VariableStructure=VariableStructure(): information about the system variables.
  • data::DataStructure=DataStructure(): information about the snapshot data.
  • optim::OptimizationSetting=OptimizationSetting(): optimization settings.
  • λ_lin::Real=0: Tikhonov regularization parameter for the linear state operator.
  • λ_quad::Real=0: Tikhonov regularization parameter for the quadratic state operator.
  • linear_operator_bounds::Tuple{Float64, Float64}=(0.0, 0.0): lower/upper bounds of the linear operator entries (used if optim.with_bnds=true).
  • quad_operator_bounds::Tuple{Float64, Float64}=(0.0, 0.0): lower/upper bounds of the quadratic operator entries (used if optim.with_bnds=true).
