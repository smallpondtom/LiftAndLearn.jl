Two-Pass Streaming OpInf

In the two-pass workflow the reduced basis $\mathbf{V}_r$ is obtained first (pass 1), e.g., with POD on a subset of the data or with an incremental SVD. In pass 2 the full-order data are projected snapshot by snapshot, $\hat{\mathbf{x}}_k = \mathbf{V}_r^\top\mathbf{x}_k$, and the reduced data are streamed into a recursive least-squares solver that updates the operators. Only reduced quantities (of size $r$ and $d$) are stored, never the full snapshot matrix.

Algorithms

Three recursive solvers are available through the algorithm keyword of TwoPassStreamingOpInf:

algorithmMethodUpdatesNotes
:RLSstandard (covariance-form) RLSrank-1 or block (rank=k)fastest; supports a forgetting factor and noise weighting Q; works without regularization if the first block has full column rank
:QRRLSQR-decomposition RLSrank-1propagates a square root of the correlation matrix; numerically robust
:iQRRLSinverse QR-decomposition RLSrank-1propagates a square root of the inverse correlation matrix; robust and avoids a triangular solve per step

The QR-based variants require a positive regularization (Γs > 0 or options.with_reg = true) and accept qr_method = :qr (Householder QR) or :givens (structured Givens rotations, cheaper for large $d$). Setting use_gpu=true stores the solver state on a CUDA device.

Typical usage

using LiftAndLearn
const LnL = LiftAndLearn

# Model structure: linear-quadratic state with linear input
options = LSOpInfOption(
    system=SystemStructure(state=[1, 2], control=1),
    with_reg=true,
    λ=TikhonovParameter(A=1e-8, A2=1e-6, B=1e-8),
)

# Pass 1: basis (here from batch POD on available data)
Vr = svd(X).U[:, 1:r]

# Pass 2: reduced data, streamed one snapshot at a time
Xhat    = Vr' * X                       # or project each snapshot as it arrives
Xhatdot = Vr' * Xdot                    # or use LnL.time_derivative_approx on reduced data
solver = TwoPassStreamingOpInf(options=options, n=r, m=1, algorithm=:iQRRLS)
LnL.stream_all!(solver, LnL.streamify(Xhat, 1), LnL.streamify(Xhatdot, 1);
                U=LnL.streamify(U, 1))

op = LnL.terminate_stream(solver)      # Operators with A, B, A2u, ...

Calling stream! inside your own loop is equivalent to stream_all! and lets you monitor the operator estimate (solver.cache.O) during streaming. To also learn a linear output map $\mathbf{y} = \hat{\mathbf{C}}\hat{\mathbf{x}}$, pass l (output dimension) and Γo to the constructor, which then returns a (state_solver, output_solver) pair; stream outputs with stream_output!/stream_output_all! and finish with terminate_stream(state_solver, output_solver).

Choosing the regularization

Γs may be a scalar $\gamma$ (meaning $\gamma\mathbf{I}$) or a full $d\times d$ matrix. If Γs is left at zero and options.with_reg = true, a diagonal Tikhonov matrix is built from options.λ, exactly as in batch OpInf, so the streamed solution matches the batch Tikhonov solution.

API

LiftAndLearn.TwoPassStreamingOpInf — Type
abstract type TwoPassStreamingOpInf

Abstract supertype of the two-pass Streaming Operator Inference solvers.

In two-pass Streaming OpInf the reduced basis $\mathbf{V}_r$ is computed in a first pass over the data (e.g., with an incremental SVD), and the reduced operators are learned in a second pass by solving the (regularized) OpInf least-squares problem recursively, one data stream at a time, with a Recursive Least-Squares (RLS) type algorithm.

Concrete subtypes:

  • RLSOpInf: standard (covariance-form) RLS.
  • QRRLSOpInf: QR-decomposition RLS (QRRLS).
  • iQRRLSOpInf: inverse QR-decomposition RLS (iQRRLS).

Instances are created with the keyword constructor TwoPassStreamingOpInf.

LiftAndLearn.RLSOpInf — Type
mutable struct RLSOpInf{T<:Real} <: TwoPassStreamingOpInf

Two-pass Streaming OpInf solver based on the standard Recursive Least-Squares (RLS) algorithm.

Supports rank-1 and block (rank-$k$) updates, a forgetting factor, and a noise covariance weighting. Construct it with TwoPassStreamingOpInf using algorithm=:RLS.

Fields

  • cache::RLSCache{T}: RLS state (operator matrix, inverse correlation matrix, gains, errors).
  • dims::Dict{Symbol,Int}: problem dimensions (:n state, :m input, :l output, :d number of columns of the data matrix).
  • termination_settings::Dict{Symbol,Any}: operator dimensions (:dims) and symbols (:syms) used by terminate_stream to unpack the operator matrix.
  • options::LSOpInfOption: standard (least-squares) OpInf options defining the model structure.
  • variable_regularization::Bool: enable the (experimental) variable-regularization RLS.
  • initial_step::Bool: true until the first update when no regularization is used, in which case the first stream initializes the inverse correlation matrix by a batch solve.

LiftAndLearn.QRRLSOpInf — Type
mutable struct QRRLSOpInf{T<:Real} <: TwoPassStreamingOpInf

Two-pass Streaming OpInf solver based on the QR-decomposition Recursive Least-Squares (QRRLS) algorithm.

Propagates a square-root factor of the correlation matrix and recovers the operator matrix by a triangular solve at every step. Only rank-1 updates (one snapshot per stream) are supported. Construct it with TwoPassStreamingOpInf using algorithm=:QRRLS.

Fields

  • cache::QRRLSCache{T}: QRRLS state (operator matrix, square-root correlation matrix, gains, errors).
  • dims::Dict{Symbol,Int}: problem dimensions (:n, :m, :l, :d).
  • termination_settings::Dict{Symbol,Any}: operator dimensions (:dims) and symbols (:syms).
  • options::LSOpInfOption: standard (least-squares) OpInf options.

LiftAndLearn.stream! — Method
stream!(obj, X, R; U, Q, Γs)

Update an RLSOpInf solver with one stream of reduced state/derivative data.

Builds the data matrix $\mathbf{D}_k$ of the stream from X (and U) according to obj.options and performs one recursive least-squares update of the operator matrix with the right-hand side R.

Arguments

  • obj::RLSOpInf: the solver (mutated).
  • X::AbstractArray{T}: reduced state snapshots of this stream, $r \times k$ (columns are snapshots). $k$ must be 1 or equal the block size rank set at construction.
  • R::AbstractArray{T}: reduced time-derivative data, $r \times k$ ($k \times r$ is also accepted).

Keyword Arguments

  • U::AbstractArray{T}=T[]: inputs of this stream, $m \times k$ ($k \times m$ also accepted). Leave empty if the model has no input.
  • Q::Union{T,AbstractArray}: noise covariance (weighting) of the stream; a scalar for $k = 1$ or a $k \times k$ matrix. Defaults to the identity.
  • Γs::Union{Real,AbstractArray}=0.0: new regularization value, only used by the experimental variable-regularization RLS.

Returns

  • D::AbstractMatrix: the data matrix $\mathbf{D}_k$ of this stream ($k \times d$).

Notes

  • If the solver was built without regularization, the first call computes the inverse correlation matrix directly from $\mathbf{D}_k^\top\mathbf{Q}^{-1}\mathbf{D}_k$, so the first stream must have at least d linearly independent snapshots.
  • When use_gpu=true, D and R are moved to the GPU before the update.

LiftAndLearn.stream_all! — Function
stream_all!(stream, X, R; U, Γs, Q, verbose)

Stream every data block in X/R (and optionally U) through an RLSOpInf solver.

Equivalent to calling stream! on each (X[i], R[i], U[i]) in order.

Arguments

  • stream::RLSOpInf: the solver to update (mutated).
  • X::AbstractArray{<:AbstractArray}: reduced state streams, e.g. from streamify; each element is $r \times k$ ($k$ snapshots per stream).
  • R::AbstractArray{<:AbstractArray}: reduced time-derivative streams matching X.

Keyword Arguments

  • U::AbstractArray{<:AbstractArray}=Vector{T}[]: input streams matching X (omit if the model has no input).
  • Γs=zeros(length(X)): per-stream regularization values used only by the experimental variable-regularization RLS.
  • Q=0.0: noise covariance weighting; 0 uses the default of stream!, a single matrix/scalar is used for every stream, otherwise Q[i] is used for stream i.
  • verbose::Bool=false: show a progress bar.

Returns

  • D::AbstractMatrix: the data matrix of the last stream.

Solver internals

LiftAndLearn.RLSCache — Type
mutable struct RLSCache{T<:Real}

State of a Recursive Least-Squares (RLS) solver for $\mathbf{D}\mathbf{O} = \mathbf{R}$, where $\mathbf{O} \in \mathbb{R}^{N \times n}$ is updated with blocks of $M$ rows of the data matrix at a time.

All work arrays are preallocated so that rls! runs allocation-light on the CPU or, with use_gpu=true, on a CUDA device.

Fields

  • N::Int: number of features (columns of the data matrix $\mathbf{D}$).
  • M::Int: block size (number of data rows per update).
  • n::Int: number of right-hand sides (columns of $\mathbf{R}$).
  • λ::T: forgetting factor.
  • O: current operator matrix estimate, $N \times n$ (note: transposed w.r.t. Operators).
  • P::Symmetric: inverse correlation matrix, $N \times N$ (upper triangle stored).
  • K: gain matrix, $N \times M$.
  • ξpre: a-priori error, $M \times n$.
  • ξpost: a-posteriori error, $M \times n$.
  • C: innovation covariance ($M \times M$) of the latest update.
  • J: accumulated cost ($M \times M$).
  • u, temp_DP, temp_PD, temp_update, temp_Ke: preallocated temporaries.
  • use_gpu::Bool: whether the arrays live on a CUDA device.
source
LiftAndLearn.QRRLSCache — Type
mutable struct QRRLSCache{T<:AbstractFloat}

State of a QR-decomposition Recursive Least-Squares (QRRLS) solver for $\mathbf{D}\mathbf{O} = \mathbf{R}$ with rank-1 (one data row per step) updates.

QRRLS propagates the upper-triangular square root $\boldsymbol{\Phi}^{1/2}$ of the correlation matrix together with $\mathbf{q} = \boldsymbol{\Phi}^{1/2}\mathbf{O}$ by QR-factorizing an augmented pre-array, and recovers $\mathbf{O}$ by a triangular solve.

Fields

  • N::Int: number of features (columns of $\mathbf{D}$).
  • n::Int: number of right-hand sides (columns of $\mathbf{R}$).
  • λ::T: forgetting factor.
  • O: operator matrix estimate, $N \times n$.
  • P::Symmetric: inverse correlation matrix, $N \times N$ (tracked for the gain).
  • K: gain vector, $N \times 1$.
  • Φsq::UpperTriangular: square-root correlation matrix, $N \times N$.
  • q: auxiliary matrix $\boldsymbol{\Phi}^{1/2}\mathbf{O}$, $N \times n$.
  • ξpre: a-priori error, $1 \times n$.
  • ξpost: a-posteriori error, $1 \times n$.
  • C::T: conversion factor.
  • J::T: accumulated cost.
  • A, temp_dO, temp_Kd: preallocated work arrays.
  • mthd::Symbol: factorization method, :qr or :givens.
  • use_gpu::Bool: whether the arrays live on a CUDA device.
  • tau: workspace for CUSOLVER.geqrf! (GPU only, otherwise nothing).
source
LiftAndLearn.iQRRLSCache — Type
mutable struct iQRRLSCache{T<:AbstractFloat}

State of an inverse QR-decomposition Recursive Least-Squares (iQRRLS) solver for $\mathbf{D}\mathbf{O} = \mathbf{R}$ with rank-1 (one data row per step) updates.

iQRRLS propagates a lower-triangular square root $\mathbf{P}^{1/2}$ of the inverse correlation matrix by QR-factorizing a small $(N+1) \times (N+1)$ pre-array, from which the gain vector is read off directly.

Fields

  • N::Int: number of features (columns of $\mathbf{D}$).
  • n::Int: number of right-hand sides (columns of $\mathbf{R}$).
  • λ::T: forgetting factor.
  • O: operator matrix estimate, $N \times n$.
  • Psq::LowerTriangular: square-root inverse correlation matrix, $N \times N$.
  • u: work vector of length $N$.
  • K: gain vector, $N \times 1$.
  • ξpre: a-priori error, $1 \times n$.
  • ξpost: a-posteriori error, $1 \times n$.
  • A: pre-array work matrix, $(N+1) \times (N+1)$.
  • temp_dO, temp_Ke: preallocated work arrays.
  • C::T: conversion factor.
  • J::T: accumulated cost.
  • mthd::Symbol: factorization method, :qr or :givens.
  • use_gpu::Bool: whether the arrays live on a CUDA device.
  • tau: workspace for CUSOLVER.geqrf! (GPU only, otherwise nothing).
